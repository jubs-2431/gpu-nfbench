High-performance ML software increasingly depends on GPU kernels, graph compilers, low/mixed-precision arithmetic, and Python-facing accelerator libraries. When these stacks fail, public issue reports about NaNs, overflow, dtype conversion, precision tolerance, incorrect outputs, compiler failures, and performance regressions often overlap, making reliable triage difficult. This paper presents an LLM-based triage system that detects and categorizes GPU numerical-failure reports. The system uses a fine-tuned FLAN-T5-base classifier for full-coverage triage and an LLM/deterministic agreement mode for high-confidence triage. To train and validate it, we construct GPU-NFBench, a 1,191-issue human-labeled benchmark from public GitHub issues across eight GPU-related repositories using a seven-class taxonomy. Weak keyword-derived labels reach only 50.5% accuracy, showing that retrieval labels are not sufficient ground truth. The fine-tuned LLM reaches 80.5% held-out accuracy and 0.778 macro F1; a deterministic voting ensemble reaches 73.8% accuracy; and LLM/deterministic agreement reaches 89.3% accuracy at 68.3% coverage. Cross-repository transfer remains difficult: leave-one-repository-out evaluation reaches 66.8% accuracy. We release the model outputs, benchmark, 250-row root-cause evidence-coded extension, error appendix, and reproducibility artifact with a Zenodo DOI.
